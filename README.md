# 책여기 (bookhere)

읽고 싶은 책을 검색하면, 내가 고른 도서관 3곳에 그 책이 있는지와 **어제 마감 기준**으로 빌릴 수 있었는지를 한 화면에 보여 주는 무료 웹이다. 로그인·위치·회원번호를 받지 않고, 결과를 링크로 공유할 수 있다.

데이터: [도서관 정보나루](https://www.data4library.kr) Open API (국립중앙도서관). 개인이 만든 서비스이며 공식 서비스가 아니다.

## 화면과 주소

| 주소 | 화면 |
|---|---|
| `/` | 책 검색 (제목·저자·ISBN). ISBN을 넣으면 바로 결과로 간다. 아래에 "내 도서관" 한 줄 |
| `/libraries` | 내 도서관 고르기: 시·도 → 시·군·구 → 최대 3곳 체크. `?from=<isbn>`이면 다 고른 뒤 그 책으로 돌아간다 |

| `/book/<isbn>?lib=<도서관 코드>` | 공유 링크. 미리보기 이미지가 "이 책, ○○도서관에 있어요"가 된다 |
| `/ask` | 문장으로 찾기 (아래 "문장으로 찾기"). `POST /api/ask` 를 부른다 |
| `/og/<isbn>[/<도서관 코드>]` | 미리보기 이미지 (`next/og`) |
| `/api/libraries?region=` · `/api/availability?isbn=&libs=&regions=` · `/api/holders?isbn=&region=` | 브라우저가 부르는 우리 API. 정보나루는 서버만 부른다 |

### 한도 보호 (팀장 지시 10/27)
- `/api/availability`: 도서관은 한 요청에 최대 3곳, 시·도 코드도 최대 3개. 형식이 틀리면 400. 도서관 코드는 함께 보낸 시·도의 도서관 목록(`libSrch`, 7일 캐시)에 있을 때만 정보나루 `bookExist`를 부른다. 목록에 없는 코드는 부르지 않고 그 줄만 "폐관했거나 자료 수집이 멈췄을 수 있어요"로 보인다 (요청 전체를 400으로 거절하면 폐관 도서관을 고른 사람이 나머지 2곳 결과도 못 본다).
- 공유 링크(`?lib=`)와 `/og/<isbn>/<도서관 코드>`의 도서관은 코드로 정보나루에 묻지 않고 17개 시·도 목록(7일 캐시)에서 찾는다 (`getLibrary`, 🛡 security 10/28). 캐시가 찬 뒤에는 코드를 바꿔도 호출이 늘지 않는다. 캐시가 비었거나 실패한 시·도는 요청마다 다시 묻는다 (캐시가 빈 순간 동시에 온 요청은 각자 부른다). `/og`는 목록에서 찾은 도서관만 `bookExist`를 부른다.
- 한도가 차서 `bookExist`가 실패한 줄은 "확인 못 함"이고, 고른 곳이 모두 실패하면 "조회가 몰려…" 상자와 다시 확인 버튼이 뜬다. "폐관했거나…" 안내는 목록에 없는 코드(`missing`)일 때만이다. 시·도 목록이 0곳으로 오면 오류로 보고 캐시하지 않는다 (한도 초과 응답 모양은 미확인).
- `/api/holders`는 도서관 코드를 받지 않는다. 시·도 코드는 17개 중 하나만 받는다 (이전 그대로).
- 더 강한 요청 제한(외부 서비스·패키지)은 넣지 않았다. 필요하면 verifier 검토 뒤 Vercel 방화벽 규칙부터 본다.

## 요구사항 질문의 답과 가정

1. **누가 언제 쓰나** → 폰으로 책 소개(SNS·서점·지인 추천)를 보다가 "우리 도서관에 있나?"를 바로 확인하는 사람. 그래서 모바일 한 줄 배치(최대 폭 36rem), 첫 화면 맨 위가 검색창, 그 아래 "내 도서관" 한 줄이다. 처음 온 사람은 검색창 아래 "내 도서관 고르기" 안내를 본다. 버튼·링크는 높이 44~48px, 글자는 15~17px, 한국어 낱말 중간에서 줄을 바꾸지 않는다.
2. **내 도서관을 안 고른 사람이 공유 링크로 들어오면** → 책 정보 + 링크에 담긴 도서관 1곳(공유한 사람의 도서관 중 이 책을 가진 곳)의 소장·대출을 "공유한 분이 고른 도서관"으로 보여 주고, "내 도서관으로 보기" 버튼을 둔다. 링크에 도서관이 없으면 "내 도서관 고르기" 안내만. 링크에는 도서관 1곳만 담기고 나머지 2곳은 담기지 않는다는 문구를 공유 버튼 아래에 보인다.
3. **3곳을 넘기려 하면** → 체크가 되지 않고 "최대 3곳까지 고를 수 있어요. 위에서 하나를 빼고 다시 고르세요."가 뜬다 (체크박스를 막아 두지 않고 이유를 말한다).
   **폐관·수집 중단이면** → 결과 화면에서 그 도서관 줄에 "정보나루에서 이 도서관 자료가 오지 않았어요. 폐관했거나 자료 수집이 멈췄을 수 있어요. 도서관 바꾸기"가 뜨고 나머지 도서관은 그대로 보인다. 고르기 화면에서 그 시·도를 열었을 때 목록에 없으면 "지금 목록에 없어요"를 붙인다. 가짜 데이터의 "(예시) 수집 중단 도서관"으로 볼 수 있다.
4. **검색 결과가 없으면** → "제목을 짧게 줄이거나 저자 이름으로, 또는 ISBN 13자리로" 안내.
   **같은 책의 여러 판** → 판마다 따로 한 줄씩 보인다 (출판사, 나온 해로 구분). 결과 목록 위에 "도서관마다 가진 판이 다를 수 있어요", 결과 화면 아래에 "찾던 판이 아닌가요? 다른 판 찾기"(같은 제목 검색)를 둔다. 판을 묶어 한 번에 조회하는 것은 호출 수가 늘어 첫 버전에서 뺐다.
5. **API가 느리거나 실패하면 (한도 초과 포함)** → 정보나루 호출은 8초에서 끊는다. 검색 실패: "책 검색이 지금 안 돼요. 조회가 몰렸을 수 있어요." 소장 조회 전체 실패: "조회가 몰려 지금은 확인하지 못했어요" + "다시 확인" 버튼 + 도서관 홈페이지 링크는 계속 보인다. 한 곳만 실패하면 그 줄만 "확인 못 함". 기다리는 동안 "찾는 중…", "확인하는 중…". 같은 책·도서관은 하루 캐시라 한도를 덜 쓴다. 다른 소장 도서관 목록은 펼칠 때만 부른다. 그 목록은 실패(우리 API가 502를 주거나 연결 실패)와 0곳(정상 응답인데 빈 목록)을 나눈다: 실패면 "목록을 받지 못했어요. 접었다가 다시 펼쳐 보세요.", 0곳이면 "같은 시·도에 이 책을 가진 다른 도서관이 없어요. 소장 정보는 한 달에 한 번 갱신돼서 최근 들어온 책은 아직 안 보일 수 있어요."
6. **"어제 기준" 날짜** → 정보나루가 응답한 시각(응답 헤더 `Date`, 캐시된 응답이면 처음 받은 시각)을 한국 시간으로 바꿔 그 전날을 "10월 26일(월) 마감 기준" 도장으로 보인다. 가정: 정보나루 대출 상태는 매일 새벽에 전날 마감분으로 바뀐다. 실제 갱신 시각이 늦으면(예: 오전 10시) 그 전에는 이틀 전 자료다 → 인증키를 받은 뒤 확인 목록 7번.
7. **접근성** → 소장·대출은 색과 함께 ○/× 기호와 글자("소장", "소장 안 함", "어제 마감 때 대출 가능", "어제 마감 때 모두 대출 중")로 표시한다. 키보드 초점 테두리, `lang="ko"`, 폼 라벨, 상태 문구 `role="status"`, 움직임 줄이기 설정을 따른다.

그 밖의 가정:
- ISBN은 숫자 10자리나 13자리만 받는다 (지시 그대로). 끝이 X인 ISBN-10은 거절되고, 검색창에 넣으면 일반 낱말 검색이 된다. 10자리는 13자리로 바꿔 조회한다.
- 시·군·구 목록은 코드표 대신 도서관 주소의 두 번째 낱말에서 뽑는다 (코드 250여 개를 추측해 적지 않으려고). 세종처럼 시·군·구가 없으면 "기타".
- "같은 지역" = 내 도서관이 있는 시·도. 내 도서관과 같은 시·군·구를 위에 보인다.
- 소장 정보는 월 단위로 갱신된다 (정보나루 MCP 활용 페이지 https://www.data4library.kr/mcpUtilization, 2026-10-27 확인: "소장 데이터는 월 단위로 갱신되어 실시간 재고와 시차가 있을 수 있습니다"). 새로 들어온 책은 최대 한 달 늦게 잡힐 수 있어서, 아래 고정 문구 둘째 줄을 "대출 가능 여부는 어제 마감 기준이고, 소장 정보는 한 달에 한 번 갱신됩니다"로 두고, 다른 소장 도서관이 0곳일 때도 같은 뜻을 붙인다. 대출 가능 여부는 API 매뉴얼대로 조회일 기준 전날이라 "어제 마감 기준"은 그대로다.
- 미리보기 이미지의 한글 글꼴은 서버가 Google Fonts에서 필요한 글자만 받는다 (`next/og` 기본 글꼴에 한글이 없음). 실패하면 글자가 네모로 보일 수 있다.
- `metadataBase`는 두지 않았다. Vercel에서는 Next가 배포 주소를 자동으로 쓴다. 다른 곳에 배포하면 넣어야 한다.

## 문장으로 찾기 `/ask` (안건 #17, 2026-11-09)

제목을 모르는 사람이 "초등 2학년 아이랑 읽을 공룡 그림책" 처럼 한 문장을 적으면, LLM 이 문장을 검색 조건으로 바꾸고 (①) 정보나루에서 찾은 후보 안에서 5권과 이유 한 줄을 고른다 (②). 책을 누르면 지금 책 화면 그대로.

- **지금은 가짜 LLM** (`lib/llm.ts`, `PROMPT_VERSION = "fake"`). 진짜 LLM 을 부르지 않고, 화면 위에 "가짜 AI로 보는 중이에요" 띠가 뜬다. 가짜인 동안 Vercel 배포 (production·preview) 에서는 `/api/ask` 404, `/ask` 404, 홈 링크 없음 (가짜는 문장 낱말을 그대로 조건으로 써서 로그·정보나루 요청에 남는다. `lib/ask/guard.ts` `askOpen`). 대표가 이 파일 하나를 통째로 바꾼다 (지킬 것은 파일 머리 주석). 다른 파일은 고칠 일이 없다
- 가짜 규칙 (화면 상태 보기): 문장에 `느림` → 8초 마감까지 기다려 오류 / `실패1` → ① 실패 → 오류 / `실패2` → ② 실패 → 폴백 / `밖` → 후보에 없는 ISBN 을 섞음 (가드레일이 뺀다) / 그 밖 → 2자 이상 낱말 2개, 후보 앞 5권, 이유 "가짜 이유". 가짜 데이터 모드 (키 없음) 에서는 낱말이 제목·저자에 하나라도 들어 있는 책이 후보 (`한강 소설` → 6권, `고양이 그림책` → 못 찾음)
- 흐름: 입력 정리 (공백, 200자, 전화·이메일·주민번호 꼴 → `[지움]`) → 하루 상한 100회 (한국 시간 0시) → ① → 조건 검사 → 정보나루 (낱말 → `srchBooks`, 0권이고 연령·주제가 있으면 `loanItemSrch`, 하루 캐시, 요청당 많아야 2건) → 부가기호·KDC 로 거르기 (5권 미만이 되면 안 거름) → ② (후보 7칸만, 50권까지) → 고른 책 검사 (후보 밖 ISBN 버림, 5권, 이유 60자) → 응답 → 기록
- 마감 8초 (요청 시작부터): ① 이나 정보나루 중에 넘으면 오류, ② 중에 넘으면 폴백 (이미 받은 후보를 대출 많은 순 10권, 이유·AI 표시 없음). 화면은 답을 15초까지 기다리고, 안 오면 (망 끊김 등) 끊고 오류
- 문장은 `POST /api/ask` 본문으로만 (주소에 안 넣음). 원문·이유 글·제목·IP 는 로그·기록·평가 파일에 남기지 않는다 (시험으로 확인)
- 기록: 요청마다 한 행 (`lib/ask/types.ts` LogRow). `SUPABASE_URL`·`SUPABASE_KEY` 가 없으면 콘솔에 `[ask-log] {...}` JSON 한 줄. 있으면 Supabase `ask_log` 에 PostgREST 로 넣고 하루 상한도 그 행 수로 센다 (**한 번도 돌려 보지 않았다**: 계정·표·RLS·키 종류는 출시 전 승인 요청 뒤 🛡 security 검수)
- 뒤로 오기: 마지막 결과 (책·이유, 문장 빼고) 를 그 기록 칸 (`history.state`) 에 두고, 뒤로·앞으로로 그 칸에 돌아올 때만 "지난번에 찾은 책이에요" 를 붙여 다시 그린다. 링크로 새로 들어오면 새 칸이라 없고, 새로고침·찾기를 누르면 지운다 (`lib/ask/client.ts`)
- 평가: `eval/README.md` (`node --env-file=.env.local eval/run.ts`, 채점은 코드)
